A coin is tossed and a die is rolled. Before the experiment, the exact result is unknown, but every possibility can be listed. A systematic list helps decide whether an event is possible, certain or impossible.

## possible outcomes, sample spaces and events

**A short exploration.**
For one coin, the sample space is $\{H,T\}$, where $H$ is heads and $T$ is tails. For a six-sided die, it is $\{1,2,3,4,5,6\}$. The event “an even number” is $\{2,4,6\}$.

:::definition Experiment and outcome
A random experiment is an action whose possible types of result are known but whose actual result is not known in advance. An outcome is one individual possibility; the set of all outcomes is the sample space.
:::

:::definition Event
An event is a subset of the sample space containing the outcomes that make its description true. A certain event contains every outcome; an impossible event contains none.
:::

**Why does this work?**
A table or tree prevents omissions in a multi-stage experiment. An outcome belongs to an event exactly when it satisfies the event description. At this stage, counting outcomes does not automatically give probability unless outcomes are equally likely.

**How to check your own work.** For a question on this topic, first state in words what is given and what must be found. Next write the rule you will use, substitute values or reason one step at a time, and then check the result in a different way: put it back into the data, estimate its size, or compare it with a diagram or number line. If two methods disagree, locate the first step where they differ instead of changing only the final answer. This habit catches sign errors, missing units and overlooked cases.

**Systems view.** possible outcomes, sample spaces and events is not an isolated trick. Follow the chain: the data determine a model, the model determines the calculation, and the result must return to the original situation. When one piece of data changes, predict whether the result should increase, decrease or stay unchanged before calculating again.

## Worked examples and applications

:::example A die sample space
List the sample space for one roll of a six-sided die.

**Solution.**
The faces are labelled $1$ to $6$, so $S=\{1,2,3,4,5,6\}$.

Therefore, $\{1,2,3,4,5,6\}$.
:::

:::example Describing an event
Roll a die. Write event $A$: “the result is greater than $4$”.

**Solution.**
In $S$, the numbers greater than $4$ are $5,6$, so $A=\{5,6\}$.

Therefore, $\{5,6\}$.
:::

:::example Two coins
Toss two coins in order. List the outcomes.

**Solution.**
Record the first and then the second coin: $\{HH,HT,TH,TT\}$.

Therefore, $\{HH,HT,TH,TT\}$.
:::

:::example A spinner and a coin
A spinner has $R,B$ and a coin has $H,T$. How many ordered outcomes are there?

**Solution.**

*Understand.* Record the given data, the required result and any conditions.

*Plan.* Choose the relevant definition or rule, then work in a logical order.

*Solve.* Each of $2$ colours pairs with $2$ coin faces: $2\cdot2=4$ outcomes.

*Look back.* Compare the result with the data and use an independent check.

Therefore, $4$.
:::

## Common mistakes and connections

:::warning What can go wrong?
- **Ignoring order when it matters.** Treating $HT$ and $TH$ as one outcome for two ordered tosses. They differ in which toss produces heads. Record the first and second positions consistently.
- **Assuming every listed outcome is equally likely.** Counting named outcomes alone and concluding likelihood. A spinner with unequal regions gives unequal likelihoods. Use counting ratios only after establishing equal likelihood.
:::

**Connections.** A sample space maps everything that can happen, while an event selects the part relevant to a question. This organisation prepares for theoretical probability and simulation. When solving a problem, separate three layers: the data, the mathematical relationship and the conclusion. Before substituting values, state why the chosen rule applies; after each step, check signs, units and conditions. A diagram, small table or simple case often reveals a missing assumption. Estimate before calculating so that you know whether the answer should be large or small, positive or negative. After obtaining a result, use an independent check: substitute it back into the data, measure it on the diagram, or test a boundary case. If one item of data changes, predict which part of the method changes and which part remains valid. This approach turns a formula into a connected system of reasons and makes the idea usable in an unfamiliar situation instead of only in a memorised exercise. It also produces written work that another student can follow, question and verify line by line.

## Summary

- An outcome is one individual possibility of an experiment.
- The sample space contains all possible outcomes.
- An event is a set of outcomes satisfying a description.
- Tables and trees help list outcomes without omissions.
- Do not automatically assume outcomes are equally likely.
